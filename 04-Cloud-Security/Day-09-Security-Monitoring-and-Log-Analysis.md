## 2. Understanding Security Monitoring

### Definition of Security Monitoring

Security monitoring is the continuous observation, collection and analysis of activities across an organisation's IT infrastructure to identify suspicious behaviour, security threats and potential incidents.

### Purpose of Security Monitoring

Security monitoring helps organisations to:

1. Detect suspicious activities and potential cyberattacks.
2. Identify unauthorised access to systems and accounts.
3. Monitor network traffic and system behaviour.
4. Detect unusual user activities.
5. Investigate security alerts.
6. Support incident response and recovery.
7. Maintain visibility into the organisation's security posture.

### Security Monitoring at Triple S Technologies

Triple S Technologies monitors:

- Employee computers and laptops.
- Business servers.
- Network infrastructure.
- User authentication activities.
- AWS cloud resources.
- Administrative account activities.
- Security configuration changes.

### Practical Example

An employee account records ten failed login attempts within two minutes, followed by a successful login from an unfamiliar device.

A SOC analyst should:

1. Review the authentication logs.
2. Identify the affected account.
3. Investigate the source IP address and device information.
4. Check whether MFA was used.
5. Verify the activity with the account owner.
6. Escalate suspicious activity for further investigation.

### Key Security Monitoring Principle

Early detection and continuous monitoring help organisations identify threats before they cause significant damage.

## 3. Common Security Log Sources

### What Are Security Logs?

Security logs are records of activities and events generated by operating systems, applications, network devices and cloud platforms.

SOC analysts examine these records to identify suspicious activities and investigate potential security incidents.

### 1. Authentication Logs

Record user login and authentication activities.

Examples:
- Successful logins.
- Failed login attempts.
- MFA authentication events.
- Account lockouts.
- Password changes.

Security concern: Repeated failed logins followed by an unexpected successful login.

### 2. System Logs

Record operating system and server activities.

Examples:
- System startup and shutdown.
- Service failures.
- Software installation.
- Configuration changes.
- System errors.

Security concern: An unexpected security service shutdown.

### 3. Network Logs

Record network communication and traffic activities.

Examples:
- Incoming and outgoing connections.
- Firewall activity.
- Blocked connections.
- DNS queries.
- Unusual traffic patterns.

Security concern: Unexpected outbound connections to suspicious destinations.

### 4. Application Logs

Record activities occurring within software applications.

Examples:
- User actions.
- Application errors.
- Access attempts.
- Database operations.
- Administrative changes.

Security concern: Unauthorised access to sensitive application data.

### 5. Cloud Security Logs

Record activities involving cloud infrastructure and services.

AWS examples:
- AWS CloudTrail: Records AWS account and API activity.
- Amazon VPC Flow Logs: Captures information about IP traffic to and from network interfaces.
- Amazon GuardDuty findings: Identifies potential security threats using analysed data sources.

Security concern: Unexpected IAM policy changes or suspicious administrative activity.

### Importance of Log Collection

Centralising security logs allows SOC analysts to correlate events from different systems, investigate incidents and identify suspicious patterns.

### Key Takeaway

Different log sources provide different pieces of security evidence. Combining them helps analysts build a more complete understanding of potential incidents.

## 4. Security Monitoring Techniques

### 1. Real-Time Monitoring

Continuously observes system and network activities to identify suspicious events as they occur.

Example:
Detecting repeated failed login attempts against an employee account.

### 2. Log Monitoring

Collects and analyses logs from servers, applications, network devices and cloud environments.

Example:
Using AWS CloudTrail to investigate unexpected IAM policy changes.

### 3. Network Monitoring

Examines network traffic to identify unusual communication patterns and potentially malicious connections.

Example:
Detecting unexpected outbound connections from an internal server.

### 4. User Activity Monitoring

Observes user activities and access patterns to identify unusual or unauthorised behaviour.

Example:
An employee accessing sensitive files outside normal working hours.

### 5. Threat Detection and Alerting

Uses security rules, analytics and threat intelligence to identify potentially malicious activity and generate alerts.

Example:
A SIEM platform generating an alert after several failed login attempts followed by a successful login.

### 6. Security Event Correlation

Combines related events from different sources to identify patterns that may indicate a security incident.

Example:
Correlating authentication logs, firewall records and AWS CloudTrail events to investigate suspected account compromise.

### Importance of Monitoring Techniques

Using multiple monitoring techniques improves security visibility, supports early threat detection and helps SOC analysts investigate incidents more effectively.

## 5. Identifying Suspicious Activity

### What Is Suspicious Activity?

Suspicious activity refers to unusual system, network or user behaviour that may indicate a security threat or unauthorised access.

### Common Indicators of Suspicious Activity

1. Multiple Failed Login Attempts
   - Repeated authentication failures against one or more accounts.
   - Possible password guessing or brute-force activity.

2. Unusual Login Locations
   - Authentication from an unexpected geographical location.
   - May indicate compromised credentials or unusual legitimate activity.

3. Unusual Administrative Activity
   - Unexpected administrator privileges or IAM policy changes.
   - May indicate privilege escalation.

4. Unusual Network Traffic
   - Unexpected outbound connections or unusual traffic volumes.
   - May indicate data exfiltration or malicious communication.

5. Unexpected File Access
   - Unusual access to sensitive files or large numbers of file downloads.
   - May indicate unauthorised data access.

6. Security Configuration Changes
   - Unexpected firewall, logging or security policy modifications.
   - May indicate an attempt to weaken security controls.

### SOC Analyst Investigation Process

When suspicious activity is detected, an analyst should:

1. Identify the affected system or account.
2. Record the event timestamp.
3. Identify the source IP address where available.
4. Review related security logs.
5. Compare the activity against normal behaviour.
6. Determine the potential impact.
7. Assign a preliminary severity level.
8. Escalate or recommend appropriate response actions.

### Important Investigation Principle

An unusual event does not automatically confirm a cyberattack.

SOC analysts must validate evidence, consider legitimate explanations and avoid making unsupported conclusions.

### Example: Triple S Technologies

A business server records unusual outbound network traffic during the night.

The SOC analyst should examine firewall logs, network flow records, server activity and authorised maintenance schedules before determining whether the activity represents a security incident.

## 6. Practical Security Log Investigation
### Investigation Scenario

Organisation: Triple S Technologies

Incident Type: Suspicious Network Activity

Affected System: FINANCE-SERVER-01

Alert Description: Unusual outbound network connections detected from a business server.

Investigation Objectives:

- Identify the source system.
- Identify the destination IP addresses.
- Count the outbound connection attempts.
- Identify unusual destination ports.
- Determine whether any connections were allowed or blocked.
- Assess whether the activity requires escalation.

Evidence Source: Synthetic firewall logs created for this training exercise.

## 7. Investigation Findings

## 7. Investigation Findings

### 7.1 Source System
The investigation identified `10.0.2.15` as the source of all eight outbound firewall events. This system represents FINANCE-SERVER-01 in the training scenario.

### 7.2 Destination Addresses
Three unique destination IP addresses were identified:

- `198.51.100.77`
- `203.0.113.50`
- `203.0.113.80`

These addresses belong to reserved documentation ranges and do not represent real external attackers.

### 7.3 Outbound Traffic Summary

| Destination Port | Number of Events |
|---|---:|
| 80 | 1 |
| 443 | 2 |
| 4444 | 5 |
| **Total** | **8** |

### 7.4 Firewall Actions

- Allowed events: 6
- Blocked events: 2

Five events involved destination port `4444`: three were allowed and two were blocked.

### 7.5 Security Assessment

Repeated outbound traffic to port `4444` is suspicious and requires further investigation. However, the port number alone does not establish malicious activity or system compromise.

The preliminary severity is **Medium**, pending additional evidence.

### 7.6 Recommended Actions

1. Identify the application or process generating the outbound connections.
2. Verify whether the destination and communication are business-approved.
3. Review endpoint detection and response telemetry.
4. Correlate DNS, proxy and network flow logs.
5. Review firewall session details to establish whether connections were completed.
6. Preserve evidence and escalate the investigation to a Tier 2 SOC Analyst.

### 7.7 Evidence Limitations

This investigation uses synthetic firewall logs. The destination addresses are documentation-only IP addresses. Firewall ALLOW and BLOCK records indicate policy decisions, not necessarily successful or unsuccessful TCP sessions.

## 8. Lessons Learned

## 8. Lessons Learned

1. Security monitoring helps organisations identify unusual activity before it develops into a serious security incident.
2. Firewall logs provide valuable information about network traffic and security policy decisions.
3. Repeated outbound connections to unusual ports should be investigated rather than automatically classified as malicious.
4. Correlating firewall, DNS, endpoint and authentication logs provides stronger evidence.
5. SOC analysts must distinguish suspicious indicators from confirmed security incidents.
6. Accurate documentation and timely escalation support effective incident response.
