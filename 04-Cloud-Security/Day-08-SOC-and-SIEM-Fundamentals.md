## 2. Understanding Security Operations Centres

A Security Operations Centre (SOC) is a centralised security function responsible for monitoring, detecting, analysing and responding to cybersecurity threats affecting an organisation's IT infrastructure.

The SOC helps protect an organisation's systems, networks, applications, endpoints and cloud environments against security incidents.

### Key SOC Responsibilities

1. Security Monitoring: Continuously monitor systems and networks for suspicious activities.
2. Threat Detection: Identify potential cyberattacks, malware infections and unauthorised access.
3. Alert Investigation: Examine security alerts to determine whether they represent genuine threats.
4. Incident Response: Coordinate appropriate actions to contain and resolve security incidents.
5. Threat Intelligence: Gather information about emerging cyber threats and attack techniques.
6. Security Reporting: Document incidents, investigation findings and recommendations.

### Example – Triple S Technologies

At Triple S Technologies, the SOC team monitors employee computers, business servers, network infrastructure and AWS cloud resources.

If an administrator account experiences multiple failed login attempts followed by unusual privilege changes, the SOC team investigates the activity and determines whether an incident has occurred.

## 3. SOC Analyst Roles and Responsibilities

SOC Analysts work at different levels depending on their experience, responsibilities and investigation complexity.

### Tier 1 – Security Monitoring and Alert Triage

Tier 1 analysts are responsible for:

- Monitoring security alerts generated by SIEM platforms.
- Identifying suspicious events and unusual activities.
- Performing initial alert investigations.
- Classifying alerts according to severity.
- Escalating confirmed or complex incidents to Tier 2.

### Tier 2 – Incident Investigation

Tier 2 analysts are responsible for:

- Performing deeper security investigations.
- Correlating multiple security events.
- Identifying attack techniques and possible entry points.
- Investigating compromised accounts and endpoints.
- Recommending containment and remediation measures.

### Tier 3 – Advanced Threat Detection and Hunting

Tier 3 analysts are responsible for:

- Conducting advanced threat hunting.
- Investigating sophisticated cyberattacks.
- Developing and improving detection rules.
- Analysing malware and advanced attack techniques.
- Improving the organisation's security monitoring capabilities.

## 4. Understanding SIEM

SIEM stands for Security Information and Event Management.

A SIEM platform collects, centralises, analyses and correlates security event logs from different sources within an organisation's IT infrastructure.

It helps SOC analysts detect suspicious activities, investigate security incidents and monitor potential cybersecurity threats.

### Key SIEM Functions

1. Log Collection: Collects security logs from servers, endpoints, firewalls and cloud environments.
2. Log Aggregation: Combines security events from multiple sources into a central location.
3. Event Correlation: Identifies relationships between different security events.
4. Threat Detection: Identifies suspicious patterns and potentially malicious activities.
5. Alert Generation: Generates notifications when predefined security conditions or detection rules are triggered.
6. Investigation Support: Provides information that analysts use to investigate security incidents.

### Examples of SIEM Platforms

- Wazuh – Open-source security monitoring and SIEM platform.
- Splunk Enterprise Security – Security information and event management platform.
- Microsoft Sentinel – Cloud-native SIEM and security analytics platform.

### Example – Suspicious Login Detection

Suppose an employee account experiences:

- Five consecutive failed login attempts.
- A successful login from an unusual location.
- An unexpected administrative permission change.

A SIEM platform can correlate these events and generate an alert for SOC investigation.

The alert does not automatically prove an account compromise. A SOC analyst must investigate and validate the evidence.

## 5. SIEM Investigation Workflow

A SIEM investigation workflow describes how security events are collected, analysed, converted into alerts and investigated by SOC analysts.

### Step 1 – Data Collection

The SIEM collects security logs from different sources, including:

- Windows and Linux servers.
- Firewalls and network devices.
- Endpoint security solutions.
- AWS CloudTrail.
- Authentication systems.

### Step 2 – Log Normalisation

Collected logs are processed into a consistent format so that security events from different sources can be analysed together.

### Step 3 – Event Correlation

The SIEM examines relationships between events to identify suspicious patterns.

For example, multiple failed login attempts followed by a successful login may indicate a potential brute-force attack.

### Step 4 – Threat Detection

Detection rules and security analytics identify activities that match suspicious behaviour patterns.

### Step 5 – Alert Generation

When a detection condition is met, the SIEM generates a security alert containing relevant event information.

### Step 6 – SOC Analyst Investigation

The analyst:

- Reviews the alert.
- Identifies the affected account or system.
- Examines timestamps and source IP addresses.
- Correlates related security events.
- Determines whether the activity is legitimate or suspicious.

### Step 7 – Incident Response and Reporting

If malicious activity is confirmed, the SOC team follows the incident response process, documents findings and escalates the incident when necessary.

### Workflow Summary

Data Collection → Log Normalisation → Event Correlation → Threat Detection → Alert Generation → Analyst Investigation → Incident Response.

## 6. Practical SIEM Investigation

### Investigation Scenario

Organisation: Triple S Technologies

Incident Type: Suspicious Authentication Activity

Affected Account: john.doe

Alert Description: Multiple failed login attempts followed by a successful login.

Investigation Objective:

- Identify the affected user account.
- Count the failed login attempts.
- Identify the source IP address.
- Determine when the successful login occurred.
- Assess whether the activity requires escalation.

Evidence Source: Synthetic authentication security logs created for this training exercise.
2026-11-27 08:10:12 FAILED_LOGIN user=john.doe src_ip=192.0.2.44
2026-11-27 08:10:35 FAILED_LOGIN user=john.doe src_ip=192.0.2.44
2026-11-27 08:11:02 FAILED_LOGIN user=john.doe src_ip=192.0.2.44
2026-11-27 08:11:29 FAILED_LOGIN user=john.doe src_ip=192.0.2.44
2026-11-27 08:12:01 FAILED_LOGIN user=john.doe src_ip=192.0.2.44
2026-11-27 08:13:15 SUCCESSFUL_LOGIN user=john.doe src_ip=192.0.2.44
### Investigation Findings

**Affected Account:** john.doe

**Investigation Results:**

1. Five failed login attempts were identified.
2. All six authentication events originated from 192.0.2.44.
3. A successful login occurred at 08:13:15.
4. The successful login occurred 1 minute and 14 seconds after the last failed attempt.
5. The activity was classified as suspicious authentication activity requiring further investigation.

### Initial Risk Assessment

**Severity:** Medium – Preliminary

**Potential Threat:** Password guessing or unauthorised account access.

**Recommended Actions:**

- Verify the login with the account owner.
- Check MFA status and authentication details.
- Review subsequent account activity.
- Escalate the alert to a Tier 2 SOC analyst.

**Evidence Limitation:**

The IP address 192.0.2.44 is reserved for documentation and training. These events are synthetic and do not establish an actual security compromise.

### Analyst Conclusion

The authentication pattern is suspicious because five failed login attempts were followed by a successful login within a short period. Further investigation is required before confirming account compromise or attributing malicious activity.

## 7. Lessons Learned

### Key Lessons

1. A Security Operations Centre monitors, detects, investigates and responds to security threats.

4. Security alerts must be investigated before confirming an incident.
5. Command-line tools such as grep and Python can help analysts investigate security logs.
6. Evidence must be validated before making conclusions about an attacker or security compromise.
7. Tier 1 analysts should escalate complex or high-risk incidents to Tier 2.
